8. **上下文效率**：SKILL 入口短、方法和底稿分层，主控要求按需读取；五角色重复许多共同段落，但单独分发时这些段落有价值。没有依据为节省 token 删除边界；可用共享协议链接减少解释成本，优先级低于前两项。

## 最弱两维的最小修改建议（仅建议，未编辑技能）

### A. 输入输出：对齐证据模板与三标签协议

位置：`hackathon-gap-research/assets/evidence-ledger.json` 的 entry_schema；同时在五角色“交接输出”后补一条引用校验说明。真实缺口是 protocol 要求研究推断带 E ID 与规则 ID，而模板没有专门位置。现有自由文本可以承载，故为中低优先级，不是阻断缺陷。

改后文本示例：

```text
交接前核对：本轮引用的 E ID 均能在同一案件 ledger 找到；方法规则 ID
均来自本角色已读 methods。若尚无 E 证据，只能标待验证假设并写空依据，
不为填齐格式制造来源。来源支持仅描述所读材料的陈述及读取范围。
研究推断填写 basis_evidence_ids、method_rule_ids、bridge_and_alternative；
字段可为空，但空缺时须明确局限，不把方法出处当市场佐证。
```

```json
{
  "basis_evidence_ids": [],
  "method_rule_ids": [],
  "bridge_and_alternative": null
}
```

收益：跨角色复核无需从一整段 claim 中猜测关联；不会增加市场采集或自动化系统需求。不需要把所有 source-index 全部加载来补齐格式。

### B. 失败恢复：区分未执行、受阻与真实读取失败

位置：主控“输出模板与失败处理”及 protocol 的标准交接段；角色仅链接共享小节即可。现有“联网失败记录 NOT_VERIFIED、URL”没有覆盖明确禁止联网或根本没有 URL 的准备阶段；现有部分保存原则也未提供恢复锚点。A1/A3 必须由执行者自行补出该区别。

改后文本示例：

```text
交接附本轮执行记录：已完成动作、未执行动作及原因、最后完成的角色/产物、
下一可执行动作。禁止/不可用而未尝试联网时写 NOT_ATTEMPTED，不写工具失败，
无 URL 则保留 null。实际尝试失败时写 NOT_VERIFIED、原 URL、读取范围与错误。
这些是动作执行记录，不替代案件业务状态；不得因此绕过用户选择关卡。
恢复时先读现有 state、ledger 与最近交接，只续做未完成动作；已写证据复用
原 E ID，避免重编号或重复计数。状态和选择事件冲突时保留原记录、暂停模式，
```

## 结论与局限

六技能的主要价值是可追踪的方法分工和严格的市场证据边界；三次新干跑均未出现跳过选择、虚构采访、预算当付款或角色共识当事实的问题。最值得改的是交接/ledger 对关联字段的承载，以及恢复记录对“未执行”的区分。没有足够依据提出新角色、新联网采集、自动发布或更复杂打分系统。未检验网络工具实况、完整真实案件文件读写、并行独立性和多轮随机漂移；本报告不替代这些行为验证。
