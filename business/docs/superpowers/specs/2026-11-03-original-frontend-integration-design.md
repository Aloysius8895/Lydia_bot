# 使用用户现有 Crew 设计接入 RAG

用户明确指出 `business/frontend` 的原设计没有被使用。本次沿用该设计作为视觉与组件依据，替换误用的 research-pwa 默认入口。已有授权包括保留一位顾问对接、后台专家路由、Claude CLI 和按职责存放代码，不需要重新选择视觉方向。

选择复用现有 React/Vite，而不是继续给独立静态 PWA 换皮；相比同时部署旧聊天服务，此方案继续使用唯一 RAG 后端与数据库。保留原 styles.css、avatars、Sidebar、MobileHome、Conversation 与主题机制，按需扩展可操作的项目和研究入口。

- 默认顾问 Steve；专家列表保留方法介绍。切换专家页不伪装成直接调用该专家，统一说明由 Steve 汇总与按题路由。
- 原 New bot 入口改为 New project，创建服务器案件，不创建没有后端的虚假机器人。项目可以切换，刷新后从后端恢复。
- Conversation 保留原聊天布局，消息来自 tasks/artifacts；长任务显示真实状态、恢复/取消，不能将轮询伪装成 token 流。
- 原右侧详情区域扩展为 Research workspace，分项目、资料、缺口、企业要求、连接设置；手机可通过详情按钮打开。来源上传/URL/检索、选择 Gap、导出、订阅确认均调用现有带会话/CSRF 的接口。
- 商业模式只允许用户明确选择 Gap 后发起；不再从前端顺序轮流调用五个专家。
- 前端使用会话接口，密码/CSRF/市场正文不写 localStorage；只保存主题偏好。退出清空私有状态；离线明确提示。
- 构建产物位于 frontend/dist；后端仅允许公开构建资源，不提供源码、配置或路径穿越。Vite 开发服务器代理至唯一后端，移除旧 API 回退。正式启动先构建原前端。
- PWA 的 manifest、icons、Service Worker 进入 frontend/public 或构建插件，缓存仅公开 shell；动态 JS/CSS 随构建版本更新，不缓存 /api。
- 旧 research-pwa 作为历史备份保留说明，不再作为默认页面；旧 frontend/server 也不在默认启动链中。

验证：先保存原界面截图作视觉参考，类型检查、现有后端测试、真实浏览器中的登录/项目持久化/来源/XSS/检索/缺口约束/取消/主题/手机/导出/退出/PWA 缓存；使用 TEST_ONLY 临时数据库，禁用真实模型，避免测试消耗订阅或混入正式案件。真实五专家和手机安装仍单独标未验收。

自查：设计源已由用户选择；不更换视觉、不新增模型供应商，不绕过已有选择和身份约束。非 Git 仓库，不初始化或提交。
