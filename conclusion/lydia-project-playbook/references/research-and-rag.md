# 专家研究、证据与 RAG

## 任务和方法加载

用户向 Steve 交付 hackathon brief、构想或企业要求。使用同一 case 的 brief、地域、全部用户类别、评分标准、限制、E 证据、任务、发现、选择与交接。缺失资料记未知，不自动继承历史 Domain 1 或具体比赛。

普通聊天和完整研究由显式开关区分，不能恢复为模型自行决定研究。模型／effort 选择作用于聊天与专家研究，辅助检索／引用检查按 adapter tier，语音和 Idea 实验台另行处理。

| 方法角色 | 主要工作 | 易错边界 |
| --- | --- | --- |
| Steve Blank | 拆假设、确定学习顺序、早期客户、最终复核 | 产品做出来不是验证成功 |
| Teresa Torres | 具体经历、故事快照、跨案机会、OST | 公开评论不是本团队做过的访谈 |
| April Dunford | 真实替代 → 能力 → 价值 → 在意者 → 类别 | 无客户时定位仍是假设 |
| Bob Moesta | 实际转换时间线、四力量、使用／购买／审批链 | 兴趣、预算、类似支出不是本方案付款 |
| Ash Maurya | 选定缺口后的一页模式、约束、最小价值与实验 | 未选 Gap 不擅自进入建模 |
| hackathon-gap-research | 状态、证据、交接、选择关卡 | 主控不是第六专家，角色共识不是市场证据 |

实际读取 `business/skills/<角色>/SKILL.md` 后按引用加载 methods、cases、source-index；主控读取 `references/protocol.md` 和 assets。S 方法来源与 E 市场证据不能混用。不要重跑 `expert-team/build_*.py` 覆盖已修订的技能。

## 原专家蒸馏的制作方法

要扩展或修订专家方法，沿用 expert-team 中的制作证据：先明确专业任务与排除范围，找本人文章／演讲／访谈等一手材料，逐篇记录发布日期、访问日期、实际阅读范围、稳定来源 ID 与限制；机构自己发布的方法、参与者访谈、第三方转述分别标识，不能都算专家本人一手。付费墙／只读片段不能声称完整读过书或影音。

每位按 writings、conversations、expression-dna、external-views、decisions、timeline 六维整理 research 底稿，保留 CHECKPOINTS 与 FINAL_CHECKPOINT；再提炼 methods、cases、source-index、sources.json、FIDELITY 和短 SKILL 入口。规则回链来源 ID，同一故事去重，不为凑模型数量虚构跨域心理规律；表达风格只服务任务，不冒充专家本人或授权人格复制。

制作顺序 Steve → Ash → Teresa → April → Bob → 主控不同于实际研究顺序。主控统一证据台账、交接、选择关卡和模板，角色间的分歧保留，不用五份重复答案替代协作。用实际方法题、边界题、团队案件、普通 AI 基线及新上下文恢复验证；静态格式／Nuwa 字符串计数不能证明方法保真。训练材料与测题重叠时写明，无真正留出不宣称泛化提升。独立上下文评估与同一运行者串行扮演需分别报告。

## 完整研究流程

Steve 问题拆解 → 实际允许的联网采集 → Teresa → April → Bob → Steve 复核 → 有依据的缺口清单 → AWAITING_SELECTION。应用阶段和 API 字段以 worker/research 为准。

用户明确选择存在的 Gap ID 后，记录原始选择事件，才进入 MODELING：Bob 购买假设 → April 差异价值 → Ash 一页模式 → Steve 验证优先级。「继续」「再查」和专家推荐不是用户选择。恢复先读持久状态，复用 E ID、已完成步骤与有效选择，不重复模型调用或复活取消任务。

候选需说明谁有问题、现有替代、谁付款、证据、反证、未知和下一步验证。可以少于预期数量或零候选，不能填假数字凑数。企业要求单独存，不等于客户已经采购；验证问题分使用者、主管、付款／审批者。未经明确授权不外联、不约访、不购买。

## RAG 的实际链路

`data/data_preprocessing/RAG`：sources 获取和清理 → retrieval 规范化、身份／版本去重与分块 → 本地 embedding + 词法混合召回 → query-expansion 中／英／马来语扩展 → rerank 候选重排 → agents 引用与语义复核。

- case、资料类型、来源版本和缓存必须隔离。扩展词和重排结果不是新增证据。
- 重排只能返回本轮候选 chunk ID；未知 ID 拒绝，零候选直接处理，不能靠模型编补。
- embedding 维度及模型指纹不匹配时不能混库；无 Ollama 保留词法能力并标降级。
- 扩展／重排失败保留原查询／原召回并记录原因。只接收完整 JSON 或完整 JSON 围栏，不从解释文本中猜 JSON。
- crawl-bridge 导入作品至 case 的 PROJECT；绑定 origin、版本、稳定引用和 outbox，旧投影失效与整体激活保持一致。

PROJECT（案例／作者自述）、MARKET（市场材料）、METHOD（专家方法）、企业要求和用户构想按当前 schema 分开。获奖作品用于参考机制，不能直接当 MARKET 需求证明；媒体报道不等于独立事实核验。

## 搜索与覆盖边界

Tavily 搜索摘要只用于发现，读正文后才决定是否形成证据。应用 `Search.reserve` 要求免费额度确认、账号、key、当月 period、正整数余量及 24 小时内确认时间。预留用事务扣减；网络失败标 UNKNOWN_CHARGED，不自动退还或切付费。不要直接改时间戳伪造额度已核实。

公网来源采集保留 URL、日期、已读范围与失败。遵守 SSRF／重定向／正文大小等现有边界。转载按同一事件或说话者去重。样本并非总体，全球资料不能直接推出马来西亚本地需求；覆盖用户类别、未消费群体、退出者与反面证据，不用数据量或复杂公式冒充代表性。

## 历史评估应如何解读

初期 nomic embedding 的六条多语言评估为 PARTIAL；后续 15 文档／15 查询的扩展重排有改善，但保留组仅 3 条，不能声称生产质量已保证。专家方法评估与普通 AI 基线均有通过记录，未证明净成功率更高。

2026-11-11 成果原型在私有库副本上真实跑通完整流程，约 183 秒，29 条发现、0 缺口。原因包括只有用户构想以及搜索额度确认过期。它证明该次流程可运行，不证明市场研究充分；旧总状态文档「真实五专家 NOT_RUN」不能覆盖这次特定证据，也不能把特定一次运行提升为所有专家质量已验收。
