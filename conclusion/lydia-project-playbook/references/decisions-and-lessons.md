# 用户决定与可复用经验

以下是从原始对话及当前实现提炼的项目约定，有适用范围，不把单次任务授权升级为通用授权。具体证据位置见 provenance 和 source-index。

| 决定／经历 | 后续应怎样做 |
| --- | --- |
| 「负责什么放什么 folder」，重复纠正 data 必须在根 data | 所有数据处理与真实资料分层；引用模块路径，不能藏回 business/.runtime |
| 原有 frontend 设计未被用、页面多次无变化 | 复用 React 正式源；检查实际 dist／进程／缓存，不能只证明代码已改 |
| Crew → Lydia，旧资料／主题偏好继续使用 | 新文案与启动器用 Lydia，旧名称兼容；历史报告不改成新品牌伪造当时事实 |
| 仅本人使用、保留 CLI、避免另买推理 key | 订阅推理和可选语音 key 分离；不擅改计费路线；当前方案不能锁死旧 Pro |
| 想和专家自然聊天，完整流程太慢／无 output | 默认普通聊天，显式完整研究开关；开关保持和模型选择记忆；先诊断 adapter |
| 用户「继续」不是 Gap 选择 | 选方向用明确存在的 ID 并持久化；缺口不足可为零 |
| 想知道样本如何代表现实总体 | 讨论覆盖、偏差、独立来源、未知与反证，不用数量或多角色投票冒充代表性 |
| 多次要求先 pic 看设计、满意再实现 | 新方向交可 review 的实际预览；同一已批准方案不重问 |
| 不喜欢蓝底、特效多、拥挤及挤占中区 | 暖灰／纯黑双主题，简化特效；大工作区／独立工具页，不全塞侧栏 |
| 触屏白块／拖动偏移／分隔线挡按钮 | 长按拾取、指针取消／坐标和 overlay 层级一起测，查看实际点击 |
| Grok 资料包共用竞赛链接误冲突 | 区分作品主身份和辅助链接；记录失败并修去重规则，不能覆盖或合并错项目 |
| 首批测试作品新增稳定 ID 被记 conflict | 同实体新 ID 需核对原字段与身份映射，不直接当新作品或静默别名 |
| 从仅手动 Drive 发展到每天 10 点 | 后续明确授权覆盖早期阶段限制；读最新代码／报告，别继续说每日同步关闭 |
| 接收新闻时某一条无 URL | 整批拒收，生产者重做有效批次并重算 ready；不伪造网址或局部偷删 |
| 可选日期 null 导致有效 27 条被拒 | 规定的可选字段 null 规范化为缺失，保留扩展字段和来源完整性；补回归 |
| 新闻没进是上游没送 news.json | 按端到端链路核实，其他 DailyNewsAutoPublish 不是 Lydia 资料源 |
| 365 天清理要求，用户选直接删除 | 保留范围和被引用保护一起实现；清理与备份保留分开，不删手写笔记 |
| 所有研究 CLI 失败只在 chat 修过 schema | schema 方言修正在所有调用统一实施，验证真实完整流程和引用约束 |
| 文字引文存在但只能支持半条要点 | 每点 1–3 段，字面核对＋语义支持复核，partial 标识；来源真实仍未知 |
| 电脑开着手机仍打不开 | 查 Tailscale 在线、睡眠、实际 HTTPS 和旧图标地址；不把本机部署称云托管 |
| 取消登录页但只本人 Tailnet 使用 | 限定自动会话条件，保留 API session／Origin／CSRF，不开放公网 |
| 打算 push main 的历史任务 | 当时任务授权不代表未来所有任务都 push；本 skill 整理不推送 |

## 冲突记录的处理

`IMPLEMENTATION_STATUS.md`、多处 README 保留早期 NOT_RUN／手动阶段和旧路径。不要全信某一个总文档，也不要静默抹掉历史：标出时间和上下文，交叉核对实现与最新执行结果。

例如深入解读 README 顶部写已上线，但后面仍保留原设计稿「如果确认」「待决定」；顶部后续更新加当前正式代码优先用于说明实现，后半用于理解当时方案。outputs-page 仍待确认则保持设计状态。

有一条 Codex 会话在其他项目安装 humanize 时提及 business_agent；它是误命中的跨项目记录，不纳入 Lydia 长期做法。应用运行目录里的大量 Claude 推理会话是研究请求／模型输出，不等同于用户开发授权，不把它们全部复制进 skill。
