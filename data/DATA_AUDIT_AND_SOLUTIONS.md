# Lydia 数据问题与解决方案

审计日期：2026-11-04（Asia/Kuala_Lumpur）。范围：当前代码、schema、API、专家工作流及已保存的测试报告。未读取真实客户正文、打开实际数据库或运行真实模型；本文不能断言当前真实资料的数量、质量分布或泄露情况。

路径说明：本报告和 RAG/database 位于 `C:\maven\business_agent\data`，与 business 同级。下文 `RAG/`、`database/` 相对于本目录；`agents/`、`backend/`、`skills/`、`expert-team/`、`test-results/` 等相对于 `../business/`。

本文中的 `population` 指研究目标总体，`sample` 指实际观察样本。网页、片段、受访者、机构和交易是不同计数单位；RAG 检索结果不是总体的随机样本。

## 核心判断

当前系统已经能够保存、检索、引用资料，并对部分不受支持的主张阻断输出；但它还不是经过验证的抽样调查或总体统计推断系统。最大缺口是：缺少总体定义、样本获取机制、独立观察单位和结论外推边界的结构化记录。增加搜索量、embedding 或模型参数都不能自动解决这些问题。

本次只实现目录迁移、引用修复和文档；下述新增字段、门禁、采集流程和统计功能均为建议，尚未接入运行系统。

## 已有且值得保留的保护

- `METHOD / MARKET / PROJECT` 分类；全局方法与项目资料隔离，方法检索可按角色过滤。
- 案件级数据隔离、参数化 SQL、事务、持久化与并发幂等控制。
- 正文规范化 hash 去重、canonical URL、来源版本、active 标记、片段原文位置。
- embedding 模型指纹/维度隔离；失败时记录原因并降级为关键词检索。
- 引用需属于当前案件、来自 MARKET，专家主张引用需在本轮读取的来源中；模型做语义复核。
- 查询扩展和重排输出不作为原始证据；缓存有案件隔离；重排明确只判断相关性。
- 公开 URL 的 SSRF 防护、限时、大小/重定向约束；搜索额度门禁。
- 测试使用独立 TEST_ONLY 数据库；已有报告公开说明真实研究与真手机验收未完成。

这些能力解决部分数据工程问题，不等于样本具有代表性或市场结论为真。

## 优先级

- **P0：在使用系统作真实市场判断前处理。** 错误会直接导致把假设当事实、把局部现象当总体结论。
- **P1：开始稳定积累真实资料时处理。** 影响质量、可追溯性、可靠运行和检索表现。
- **P2：数据规模或协作需求上升后处理。** 先测量瓶颈，再增加工程复杂度。

## 逐项问题、影响和解决方法

### 01 · 未结构化定义目标总体与观察单位〔P0，已确认缺口〕

**代码证据：** `database/schema.sql` 的 cases 只有 title、brief、region 等通用 meta；documents 记录正文与来源，没有强制的 population、sampling frame 或 observation unit。自然语言 brief 可以提到人群，但未被结构化校验。

**影响：** “马来西亚诊所”“巴生谷私人牙科诊所”和“诊所患者”可能被混用；30 篇文章不能按 30 家诊所计算。

**解决：** 每个研究问题定义 `target_population`、纳入/排除条件、地区、参考时间、观察单位、估计目标。例如以“机构”为单位估计采用率，或以“预约”为单位估计爽约率，两者分母不同。允许探索阶段填 unknown，但禁止在范围未知时发布总体比例。

**验收：** 一个关于患者的证据不能被用来计算诊所比例；每个量化结论显示其分子、分母、单位、时间和范围。没有这些字段只能输出局部观察或待验证假设。

### 02 · 网页搜索产生便利样本与覆盖偏差〔P0，风险已识别，实际偏差未测量〕

**代码证据：** `RAG/search.ts` 请求最多 5 个搜索结果；`agents/worker.ts` 自动采集前 3 个。关键词、搜索排序、平台、语言、可抓取性决定资料能否进入系统。

**影响：** 会发帖的人、SEO 较强的企业、英文内容、城市和数字化程度高的机构可能更容易出现；未上线的人、沉默用户、失败企业可能缺席。文章越多不一定越代表总体。

**解决：** 建立样本来源台账；标记搜索资料为 discovery/convenience。按与问题相关的地区、机构规模、客户角色、使用/未使用状态等列覆盖矩阵；寻找缺席群体、线下或合作渠道、官方统计/名录作为参照。覆盖矩阵用于发现缺口，不宣称填写完即取得统计代表性。[Census 非抽样误差标准](https://www.census.gov/about/policies/quality/standards/standardd3.html)

**验收：** 报告显示资料来自哪些渠道、覆盖哪些群体、遗漏哪些群体；仅有便利样本时，系统不能把出现频率写为总体发生率。

### 03 · 缺少抽样设计、响应情况和推断权限〔P0，已确认缺口〕

**代码证据：** schema/API 未建模抽样框、纳入概率、邀请数、拒访/失访、抽样层/群、权重来源；没有总体估计器。

**影响：** 用 `n` 直接套误差范围公式会产生虚假精确性。没有选择机制，无法仅靠数据量确定能否推断总体。

**解决：** 先明确用途：机会探索可用目的抽样/访谈，但只作探索；估计发生率需要适合的概率抽样设计，或明确建模假设、外部参照与敏感性分析的非概率推断。记录 sample design、frame、招募/响应过程、基准数据及权重版本。概率样本也仍有覆盖、非响应和测量误差。[AAPOR 非概率抽样报告](https://aapor.org/wp-content/uploads/2022/11/NPS_TF_Report_Final_7_revised_FNL_6_22_13.pdf)

**验收：** unknown/convenience 样本默认不输出设计型误差范围或无条件总体比例；非概率模型估计显示模型、假设与不确定性来源。[AAPOR 区间解释](https://aapor.org/statements/understanding-a-credibility-interval-and-how-it-differs-from-the-margin-of-sampling-error-in-a-public-opinion-poll/)

### 04 · 无独立受访者/机构/事件实体，重复材料可能被当作多份支持〔P0，已确认缺口〕

**代码证据：** `RAG/retrieval.ts` 去重主要基于正文 hash 和 URL；没有 participant、organization、event 或 source-family 实体。相同报道被改写后仍可能是不同 document。

**影响：** 同一个客户被三篇报道引用、同一新闻被十站转载，不等于多个独立观察。一个用户的多次预约也不是独立用户样本。

**解决：** 区分 `document_count / independent_source_count / participant_count / organization_count / event_count`；用匿名 subject ID、事件 ID、原始来源族、转载关系和人工可复核的实体匹配管理依赖。近似去重只提出候选，不能自动把同名人或相似机构合并。

**验收：** 一份新闻的十个转载只能计为一个独立来源族；重复观察可保留，但统计时按设计处理聚类与依赖。

### 05 · 日期、地区、身份及方法学信息不完整〔P0，已确认缺口〕

**代码证据：** 网页 `ingestURL` 将 published_at、speaker、region 初始化为 null；上传 API 有部分字段但不强制来源核验。缺少研究时间、原始样本和问卷/测量口径。

**影响：** 海外数据、过期数据、供应商宣传、客户原话可能被混用。抓取时间不是事件时间或研究时间。

**解决：** 保存发布时间、观察时间、抓取时间、作者/机构、地区、人群、原始研究链接、资料类型、验证状态与未知项。先人工/规则辅助补齐，AI 提取结果标为待审核，不能伪填未知值。

**验收：** 日期未知不能自动称“最新”；海外资料用于本地判断必须显示适用性限制；能追到原始研究和其定义。

### 06 · 引用支持、事实真假和总体代表性尚无独立门禁〔P0，部分保护已存在〕

**代码证据：** `agents/citations.ts` 明确只复核片段是否支持主张；UNSUPPORTED 会阻断，但 UNCERTAIN 可返回结果。`SOURCE_SUPPORTED` 不包含总体代表性判断。复核与生成都使用 Claude CLI，不是独立的人类审查。

**影响：** “网页确实这么说”仍可能是错误、偏见或不适用于目标总体；模型彼此同意不能替代独立验证。

**解决：** 分开记录 relevance、citation support、source verification、sample/inference eligibility；UNCERTAIN 需在主张及导出中明确呈现，对比例、因果、付费意愿等重要结论增加独立审核和明确推断约束。避免合并成一个看似精确的“可信度百分比”。

**验收：** 本地 3 家机构的引用即使 SUPPORTED，也不能升级为“全国普遍需求”；未独立验证的内容不显示“已验证事实”。

### 07 · 合成资料仅有标签，未在生产证据路径强制隔离〔P0，已确认缺口〕

**代码证据：** 上传 API 接受 `synthetic`；`retrieve`、`checkEvidence` 的 MARKET 查询没有 synthetic=false 约束。已有测试数据库隔离是良好措施，但真实项目也可以上传 synthetic=true 文本。

**影响：** 合成示例若进入真实案件，可能被引用成真实需求。synthetic=false 也只是声明，不是真实性证明。

**解决：** 规定数据用途与环境：production、simulation、test；在检索、主张保存和导出三个边界强制区分。模拟研究可以引用合成数据，但结果需全程保留模拟标记，不能转成真实市场证据。

**验收：** 混合 synthetic=true/false 的生产案件中，合成数据不能支持真实市场主张；有专门反例测试。

### 08 · 缺少反证与非客户的系统性采集〔P0，风险，需实际评估〕

**代码证据：** Gap schema 有 counterevidence 字段，是现有优点；但采集主要由项目标题/问题形成搜索查询，没有独立的反证覆盖检查。

**影响：** 若只搜索“为什么需要产品”，会忽略没有问题的人、替代方案已足够的人和不愿购买的人。

**解决：** 每个关键假设维护支持证据、反证、未覆盖人群和下一步验证。设计中性问题，主动寻找“未采用/放弃/无痛点/替代方案有效”的案例；不能为了数量平衡而捏造反证。

**验收：** 无反证时显示“尚未系统寻找/找到”，不默认“没有反证”；增加真实但不支持产品的样本题。

### 09 · 网页抽取可能带入导航噪音或丢失关键结构〔P1，代码限制已确认〕

**代码证据：** `RAG/sources.ts` 使用正则去 HTML 标签；支持 HTML/text/JSON，PDF 需先转文本；1 MiB 页面限制，正文截到 150000 字符并标 PARTIAL。未实现浏览器动态正文/OCR/表格语义解析。

**影响：** 导航和广告可能留下；表头、单位、脚注、限定条件或后半段被截断后，解释可能改变。

**解决：** 保留受控原始快照与提取文本、提取器版本、内容类型、截断原因；引入正文提取和结构化表格路径，PDF 按页保留位置；低质量与截断资料进入待审核区。按用户实际资料格式选择工具，不必一次支持所有格式。

**验收：** 用长文、表格、动态页、乱码、PDF/OCR 错误样例检查正文/单位/脚注；PARTIAL 不能被报告当作完整阅读。

### 10 · 字符分块可能拆散定义、否定和适用条件〔P1，代码限制已确认〕

**代码证据：** `splitText` 默认按约 1300 字符切分，尝试换行边界，无 overlap；记录 heading 与字符位置，但未把完整父段落/标题链送入所有检索上下文。

**影响：** 方法的“何时不用”、研究的分母或相邻反例可能与主张分开。

**解决：** 先比较按段落/章节分块、有限相邻上下文或父块检索；检索表示可附文档/章节背景，但原文与生成背景必须分开保存。根据真实查询测试选择，不把 overlap 或块大小当通用公式。[Anthropic Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval)

**验收：** 对否定、条件、表格和跨段定义题，检索结果包含必要限定；能定位原文，生成摘要不冒充原文。

### 11 · 检索相关性不等于资料质量或总体覆盖〔P0/P1，已确认职责边界〕

**代码证据：** `retrieve` 用关键词、向量距离阈值与 RRF；每个文档最多 3 块；`rerank` 明确只判断 query relevance，未按独立来源族或样本覆盖选择证据。

**影响：** 12 个高度相关片段可能全部来自相似渠道；排名分数不代表统计权重、真实性或代表性。

**解决：** 检索先过滤用途/范围/版本/审查状态，再做相关性排序；增加可解释的来源族限制、缺口提示及冲突证据呈现。若需要估计比例，应使用定义好的结构化样本集与统计管线，不能把 Top-K 当数据分母。

**验收：** 重复宣传材料不能挤掉独立原始研究；报告不将 relevance、RRF score 或 vector similarity 转成客户支持率。

### 12 · 多语言效果与真实场景泛化尚未验收〔P1，报告已确认〕

**证据：** `test-results/retrieval-evaluation.json` 的早期本地检索为 PARTIAL；`rerank-evaluation.json` 为 15 条合成查询、最终新 holdout 仅 3 条，明确不保证生产质量。

**影响：** 小样本高分不能证明中英马来语、混合语言、口语、行业术语及无答案场景均可靠；来源语言覆盖与检索语言能力也不同。

**解决：** 建立来自真实任务的冻结评估集，分语言、领域、问题难度、无答案/反证场景；将同一来源的翻译、近重复、同模板题分组切分，防止泄漏。分别测候选召回、排序、引用支持和完整答案质量。

**验收：** 开发集与未参与调优的测试集分开；按分组报告样本量、失败例和门槛；不只汇报总平均或 MRR。

### 13 · 来源版本可保存，但主张绑定与用户复核还不充分〔P1，部分保护已存在〕

**代码证据：** 专家运行 provenance 记录 source_id、version、position；检索过滤 active 文档。但 `checkEvidence` 只检查 MARKET/source_id 所属案件，主张 evidence_ids 是来源级数组，未强制 FK 到精确 document/chunk/version；snapshot 的 evidence 返回历史版本。

**影响：** 新旧版本可能共享来源 ID；后续读报告时容易只看到来源名，难判断当时哪一段支持哪一条主张。

**解决：** 建立 claim-to-evidence 关系，绑定 document_id、chunk_id、版本、摘录和位置，保存审核结果；历史导出保持不可变，旧证据不静默替换，新研究显式标识过时来源。

**验收：** 更新同一网页后，旧报告仍能还原旧引用；新研究不会把旧文段误标成最新版。

### 14 · 项目资料入库后未必进入专家上下文〔P1，已确认路径差异〕

**代码证据：** 上传 API 允许 PROJECT，手动 retrieve 支持 PROJECT；`agents/research.ts` 自动专家路径检索 METHOD 和 MARKET，case brief/meta 会注入，但没有单独检索 PROJECT 文档。

**影响：** 用户上传的比赛规则、约束或内部背景可能“存了却没被专家读取”。把规则放进 MARKET 又会混淆证据性质。

**解决：** 明确资料用途路由：PROJECT 约束单独检索/加载，METHOD 提供方法，MARKET 支持市场主张；项目约束不能被当作客户需求已存在的证据。

**验收：** 只写在 PROJECT 文档中的明确约束可以影响分析，而该文档不能证明市场发生率或付费意愿。

### 15 · embedding 降级后缺少专用补建索引流程〔P1，已确认未见专用实现〕

**代码证据：** ingest 失败记录 KEYWORD_ONLY；再次导入相同 hash 时直接返回 duplicate；模型指纹变化后检索排除旧向量。当前检查范围未见 re-embed/backfill 作业。

**影响：** 服务恢复或模型更换后，部分资料可能长期只参与关键词检索，用户未必知道有效向量覆盖率。

**解决：** 增加索引状态统计与可恢复 backfill；按文档/模型版本幂等处理、有限批量、失败重试和取消；正文版本与索引版本分开。

**验收：** 离线导入→服务恢复→补建后不新增重复证据；旧模型向量不混入新空间；覆盖率可见。

### 16 · 方法库有来源和角色，但应用内行为仍需验证〔P1，不能说没有测试〕

**证据：** `skills/` 和 `expert-team/` 已有方法制作、来源和独立测试；应用 skills 会校验路径/hash，METHOD 检索按角色。`IMPLEMENTATION_STATUS.md` 仍标真实应用五专家流程与基线 NOT_RUN。

**影响：** “文件加载成功”与“任务中正确使用方法”是不同指标；新增博客也可能引入第三方误读或超出适用范围的规则。

**解决：** 精简稳定核心方法，资料库按需检索；新增资料先审核来源/适用条件/冲突，再版本化发布；用未参与制作的任务比较普通模型、技能、技能加检索三种表现。

**验收：** 能解释何时不适用、主动承认证据不足、不将专家方法当客户事实；保留真实输出与错误分类。

### 17 · 缺少真实数据的质量监控与退出/纠错流程〔P1，已确认未见完整管线〕

**代码证据：** 已有抓取状态与 embedding 错误，未见覆盖完整性、来源族重复率、待审核量、撤回/纠错影响传播的统一机制。

**影响：** 坏资料进库后即使发现错误，也难快速知道哪些主张和报告受影响。

**解决：** 展示缺失字段、待审核来源、重复族、索引覆盖、过期/截断资料；提供隔离、纠正、撤回与关联主张标记。明确访问权限、保留期限、脱敏和允许发送到云模型的范围；已有身份/会话保护仍保留。

**验收：** 撤回一个来源可定位受影响主张；含敏感字段的演示资料在进入云端推理前按配置阻止或脱敏，不假定本地存储意味着不出网。

### 18 · 备份恢复、缓存增长和规模性能尚缺完整验收〔P1/P2，风险未量化〕

**代码证据：** PGlite 本地持久化已有测试；settings 同时存配置与扩展/重排缓存，缓存读取判断过期但未见定期清除；schema 未建 ANN 向量索引，向量查询按距离排序。

**影响：** 大数据量下可能变慢、缓存累积；持久化通过不等于备份可恢复。当前未证明数据量已造成瓶颈。

**解决：** 先记录实际文档/块数、容量和检索延迟；建立停止写入后的一致备份与隔离恢复演练，记录版本；明确缓存 TTL 清理。达到实测瓶颈后再考虑适配当前 PGlite/pgvector 能力的索引或独立数据库。

**验收：** 从备份恢复到独立目录后记录数/关键 hash/引用一致；报告 p50/p95 延迟；优化前后用同样负载比较。

## 如何处理 sample → population，而不制造虚假精确性

以下是拟议规范，不是当前已实现字段。

1. 明确目标：发现问题机制，还是估计“多少比例的人遇到问题”。两者可共享资料，但验收标准不同。
2. 定义单位和估计量：例如“符合条件诊所中的采用比例”或“观察期内预约的爽约率”，避免混分母。
3. 核实可用抽样框与覆盖：名单缺了谁、哪些人无法进入样本。
4. 保留选择/响应过程：不是只记录成功访谈的人，还需记录邀请与无响应的可用汇总。
5. 先分层看差异与缺口，再判断能否合并；分层维度应与研究问题有关，不盲目增加维度。
6. 需要权重时记录概率设计或模型依据、总体参照、重叠覆盖和极端权重；未知概率不能伪造。
7. 若仅有便利样本，输出样本内结果和假设。若采用模型推断，明确其额外假设、验证与敏感性。
8. 统计不确定性与覆盖/非响应/测量误差分别说明。一个置信区间不能涵盖所有偏差。

不要用 `样本数量 × 放大系数`、embedding 相似度、来源篇数或多模型投票当作代表性证明。

## 建议新增的数据契约

| 对象 | 建议字段 | 规则 |
| --- | --- | --- |
| Study / 研究问题 | target_population, eligibility, geography, reference_period, observation_unit, estimand, intended_use | 未定义时允许探索，限制总体推断 |
| Sampling / 样本设计 | design_type, frame_description, inclusion_probability_known, recruitment_channel, strata/cluster, benchmark_version | unknown 与 nonprobability 显式标记；不伪造概率 |
| Observation / 观察 | anonymized_subject_id, organization_id, event_id, observed_at, selection/response status, measurement_definition | 与网页文档分开；重复观察保留依赖关系 |
| Source / 来源 | original_source_id, source_family_id, document_type, author, publisher, dates, region, language, verification_status | 出版社/域名不是事实正确性的保证 |
| Evidence / 证据 | document_id, version, chunk_id, quote, position, synthetic, truncation, extraction_version, allowed_use | 原文、翻译、摘要和模型推断分开 |
| Claim / 主张 | claim_type, target_scope, numerator/denominator/unit if applicable, evidence_links, citation_support, inference_eligibility, limitations, review_status | 禁止范围扩大；证据不足不能强行升格 |

不必现在给每个维度建立复杂的人格或现实模拟模型；先让资料可追溯、样本边界可见、推断规则可执行。

## 推荐实施顺序及完成判据

### 第一阶段：阻止明显错误的外推（先做）

- 研究范围/单位/用途表单与验证；资料用途与合成数据隔离；重要主张显示样本范围。
- 建立来源/样本台账、独立来源计数；总体系数和置信区间需要明确设计依据。
- 用反例验证：单个海外网页不能推出本地总体比例；三份转载不能变三个独立客户；合成资料不能支持真实主张。

### 第二阶段：提高真实任务中的可读性与检索质量

- PROJECT 专用上下文路由、精确版本引用、网页/表格提取审查、补建 embedding。
- 建立冻结真实任务评估集，包含跨语言、冲突、无答案、不同人群和老版本来源。
- 完成应用内真实专家流程；对照普通模型，分别评价方法使用、证据支持和结论边界。

### 第三阶段：根据真实需要开展总体估计

- 对指定行业/地区设计采集方案，先确认名录、招募渠道和统计目标；不预设一个适用于所有项目的样本量。
- 选择设计型或有明示假设的模型型估计路径，实施响应/覆盖诊断、权重与敏感性分析。
- 只有统计方法和数据都满足要求时才展示总体估计；探索材料仍单独展示。

### 第四阶段：规模与运维

- 备份恢复演练、数据撤回/纠错、缓存清理、容量和性能基准；按实际瓶颈优化。
