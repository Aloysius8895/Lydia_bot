# 持续专家语音通话 · 实施与验收

日期：2026-11-05（Asia/Kuala_Lumpur）。依据：[v1.3 Prompt](../business/docs/prompts/2026-11-05-continuous-expert-voice-call-prompt.md)，架构见 [voice-call-design.md](voice-call-design.md)。

**持续通话代码已实现；用户报告可以接通，但随后发现慢回复及 CLI_SCHEMA_MISSING。已修复 schema 兼容问题，并完成两轮真实 Claude CLI 文本验证。新版本的完整麦克风 → 朗读体验、10 分钟通话及手机仍需实测，不能用文本调用代替。**

## 2026-11-05 实际故障修复与测量

- 用户实际失败轮次：35.304s、26.612s（服务端总耗时），队列等待均为 0；其中一次上下文组装仅 141ms。原配置真实复现 CLI 生成 26.484s，约 1393 个输出 token，返回围栏 JSON，长文本中含未转义引号。
- CLI 2.1.143 对 Zod 生成的 Draft 2020-12 `$schema` 声明存在兼容问题：实际流式 init 中工具列表为空，未返回 `structured_output`。仅移除该顶层声明、保留字段约束后，init 出现 StructuredOutput，返回结构化对象。应用仍使用原 Zod schema 和证据规则验证，不宽松修复错误 JSON。
- 对话专用 CLI profile 使用短系统提示、当前模型的 low effort，并且仅允许内部 StructuredOutput 返回工具。无 shell、文件或网络工具开放；研究工作流保持原 profile，模型与订阅策略未更换。
- 通话输出不再必须同时生成两份回答；默认用 spoken_text 生成字幕。空的补充字段由应用填充，保留必要来源/限制/候选动作。
- 对话提示明确“先完成当前请求”：大纲直接解释项目，比较给出判断，方法技能的研究交接格式不用于每轮聊天；减少固定开场、重复追问，承接历史与被打断的部分。自然程度仍需要用户实际评价。
- 未回答期间相同语音文本不再次取消/入队；回答失败切到明确失败状态，麦克风保持可用，手动重试使用新轮次。网络不确定时仍使用原幂等键，避免重复消耗。
- 最终两轮真实 CLI 文本测试：项目大纲 **7.707s**（认证 615ms、生成 7088ms、233 输出 token）；承接第二个方向的追问 **7.575s**（认证 414ms、生成 7161ms、238 输出 token）。均收到原生结构化输出并通过字段/声明引用检查。这不是独立事实核验，也不是语音端到端延迟保证。
- 原生产通话正文未改写；真实复现仅使用已确认的订阅，无付费 API 后备。计时报告只保存数字与状态，不保存对话正文或账号凭据。见 [真实 CLI 测量](results/call-cli-latency-repair.json)。

已完成公开页面 REA、官方 API 调查与可选 TTS 接入，见 [ElevenLabs 调查与接入说明](elevenlabs/README.md)。原 Claude CLI 与 STT 保留；默认仍是浏览器朗读。需要用户在 Settings → 语音配置自己的 Key、读取音色并明确保存服务选择后才启用云端通话朗读。试听是明确点击的固定文本操作，使用账户额度。

类型检查、前端构建、84 项单元/API 测试及完整浏览器测试通过。ElevenLabs 的 API 和媒体在测试中均为本地替身；没有真实合成、收费、克隆或声音质量验证。Key 加密保存、不会返回 API 响应；取消/挂断会停止音频请求。浏览器支持 MediaSource 时流式播放，否则显示完整缓冲模式，CSP 仅新增同源 blob 媒体权限。

REA 在独立未登录浏览器中观察到创建声音页跳转登录，静态分析 201 个可观察脚本；登录后的克隆流程没有验证，后台语音模型不在前端分析覆盖内。原始证据、哈希和限制见 audio/elevenlabs/evidence。

## 实现的默认体验

接通并授权 → 浏览器识别真实启动后才建立通话/计时 → 问候一次 → 自动倾听 → 停顿且最终转写确认后自动提交 → 指定专家回答并朗读 → 自动继续倾听。

专家说话时可直接开口纠正；旧朗读停止，最新输入完整保留。思考时补充将原问题与新条件合并，取消旧轮次后才提交最新意图。麦克风为静音开关；单独提供停止播放、恢复语音、文字补充及回答重试。记录仍可查看、更正、导出和删除。

## 真实测试与测量

本地服务已启动在 `http://127.0.0.1:4318`。在 Projects 选择真实要讨论的项目，再选专家并接通；不需每轮发送。

1. 中文说“我们预算不到五千，不想做硬件”，检查数字和否定词；专家应自动回答。
2. 连续追问“刚才第二点是什么意思”“如果只有两千呢”，检查上下文承接。
3. 专家回答时说“等等，我说的是另一个预算”，检查是否停止旧声音且新输入开头完整。
4. 专家思考时补充限制；检查回答是否同时保留原问题与新条件。
5. 测静音/取消静音、短暂停顿、长沉默、识别恢复、后台暂停、重新恢复及挂断释放。
6. 至少持续 10 分钟并完成 10 轮；中文与英文分别测试，耳机与扬声器分别记录。未测项目保持待验收。

## 限制与费用

- 保留 Claude CLI 订阅与共享串行队列；非流式生成依旧会等待，不承诺真人电话级时延。没有自动更换模型或收费 API 回退。
- 浏览器 STT 可能由厂商在线处理，处理位置在界面说明；不承诺完全离线。TTS 是否本机取决于实际音色。
- Web Audio 输入的回声消除约束不能证明浏览器识别器的独立输入路径也已消除回声；当前文本筛选是保护措施，复杂回声/噪声必须实测，建议先用耳机。
- 背景/锁屏不承诺保持通话；进入后台主动暂停，返回后手动恢复。刷新不自动开麦。
- 无本地 STT 配置，无模型下载、依赖安装或新增数据库迁移。应用临时分析音频但不保存或上传原始音频，浏览器自身 STT 数据流单独说明。
- 历史上下文包含最近完整轮次与有限较早片段，并明确遗漏；不声称无限记忆。用户/AI 通话不是市场证据或真人访谈。
- 当前文字聊天标题仍由原有 Steve 统一入口控制；拨给其他专家时，通话卡片、实际加载技能、服务端角色与记录身份一致。
