## 现在为什么会穿模

对应 `business/frontend/src/components/KnowledgeScene.jsx`：

1. **地面和书架是一层 SVG，文件夹是叠在上面的另一层 DOM 按钮**（第 74–87 行）。两层之间没有共同的前后顺序，后排的文件夹永远压在前排书架的立柱和边线上面。
2. **SVG 的 viewBox 固定为 `0 0 1060 H`**（第 74 行）。等距投影后 x 为负的部分，即资料较多时左下方的书架和地面，会被 SVG 裁掉。文件夹按钮不受这个裁剪影响，于是看起来悬在空中。iPad 截图左侧 devfolio、imaginecup 那几排就是这种情况。
3. **区名标签放在地面外侧**（第 83 行 `iso(-70, …) - 80`），新闻库按媒体分行，每行一个标签，所以标签互相叠在一起，也压住了文件夹（新闻截图）。
4. **文件夹贴图比书架格子高很多**（96px 图片对应约 31px 高的架层），所以一定会顶穿上一排。

## 新设计如何消除穿模

- **所有几何体只在一个 SVG 里绘制**，按固定顺序从后往前画：墙 → 地面与网格 → 区块、货道、空位、区名 → 阴影与选中光圈 → 书本。书本按深度（x+y）排序，每本书都是独立的小立方体。
- **不再用高书架**：书直接放在地面货道上，区名和数量印在区块的前沿，书只会向后上方延伸，不会压住文字。
- **文字放进屏幕空间的覆盖层**：选中的项目显示带颜色色块的标签，在托盘里的显示编号。放大到区域级别才出现标题小标签，并且做碰撞检测，重叠的标签直接跳过，不会叠在一起。
- **世界坐标不受固定 viewBox 限制**（`overflow: visible`），相机根据实际边界框来适配视野，不会再裁掉任何部分。

## 颜色

- **默认方案（01–07）：每个标题一种颜色。** 从 12 色仓库色板中，用标题哈希挑选颜色；同一货道里相邻的书如果撞色会自动错开。色板为纸箱、象牙、钴蓝、钢灰、铁锈、橄榄、鼠尾草、梅紫、沙色、炭灰、纸白、砖红。同一个项目的颜色在右侧详情和托盘中保持一致。
- **备选方案（08）：按主题配色**，例如 AI 智能体、DeFi / Web3、IoT / 硬件、太空。好处是颜色带有含义，代价是同一区里会有很多同色的书。
- 选中状态统一用青绿色，参考图中的选中区也是这个颜色，不和书的颜色冲突。

## 流畅度

现有实现每次手指移动都会调用 `setZoom` / `setPan`（第 23、55、60 行），React 每帧要重建整个场景、37 个按钮，以及每张图片的 `drop-shadow` 滤镜。

原型中的做法：

- 平移和缩放只修改外层容器的 `transform: translate3d() scale()`，属于合成层操作，不重建几何体，也不触发 React 渲染。拖动期间加上 `will-change`，松手后移除，让浏览器重新栅格化，保证清晰。
- 平移带惯性；滚轮和双指缩放都以手指或光标所在位置为中心；双指和单指之间切换不会跳动。
- 「查看整个书库」、区域聚焦和 +/− 按钮都使用 0.26–0.56 秒的缓动镜头动画。
- 等距和俯视之间做 0.46 秒的投影插值过渡，屏幕中心对应的地面点保持不动。
- 切换楼层（比赛项目 / 新闻资料）时淡入淡出。
- 不使用 CSS 滤镜，阴影直接是地面上的多边形。

无头 Chrome 中，拖动和滚轮期间的帧间隔中位数为 6.1ms，p95 为 6.2ms，场景共 837 个 SVG 节点。这只是浏览器模拟结果，不代表真实 iPad 的表现。
