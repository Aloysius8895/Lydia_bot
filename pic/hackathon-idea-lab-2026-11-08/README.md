## 这版围绕什么

项目库收集 Hackathon 比赛项目，Lydia 负责分析与研究。用户将多个比赛项目拖到分析区，比较共同点，基于选中的案例提出几个适合的候选 idea；用户将喜欢的候选拖到专用书架保存。

本版取代上一版以 PROJECT / MARKET / METHOD 资料册为主导航的概念。这三种内部用途仍可保留，但不作为用户浏览比赛项目的主要方式。

## 三种布局及推荐

| 布局 | 优点 | 代价 |
| --- | --- | --- |
| 三栏实验台（推荐） | 项目、比较、收藏同时可见，拖拽距离短 | 需要控制结果卡片长度 |
| 全屏 3D 工作室 | 最接近录屏的沉浸空间 | 分析文字难读，初版模型与镜头工作量更大 |
| 分步骤比较向导 | 手机和键盘使用清楚 | 反复增删案例与拖拽收藏不够直接 |

推荐三栏实验台，只在中央桌面和收藏架使用 3D；项目内容、分析文字和操作使用二维界面。

## 核心流程

1. 在左侧项目库按赛事、主题、技术栈查找项目，预览资料完整度与来源。
2. 拖入中央实验台；建议每轮 2–6 个项目，重复拖入不新增副本。移除只改变本轮选择，不删除原项目。
3. 可选设置地区、目标用户、比赛主题、团队技能、人数、时间和预算。未填写的条件保持“未指定”，生成时明确假设，不声称个人适配。
4. 点击“分析并生成”，避免每次拖动都触发模型调用。
5. 先显示共同点、关键差异和资料缺口，再显示默认 3 个、可选最多 5 个候选 idea；材料不足时允许少交或不生成。
6. 将候选拖到右侧“我的 Idea 书架”，也提供“收藏”按钮。显示保存中、保存成功及失败重试；成功后可撤销本次收藏。
7. 从书架打开 idea，查看来源、分析、备注和版本；明确点击“交给 Lydia 研究”后才新建或关联研究任务。

## 面板布局

左侧约 22%：Hackathon 项目库，项目卡含名称、赛事、年份、主题、技术栈、来源与可拖拽手柄。奖项只展示有依据的状态；缺少的内容显示未知。

中央约 52%：Idea 实验台。上部为低矮等距桌面，选中的项目用独立档案物件表示，并提供文字选择条和移除按钮。中部显示约束与分析按钮；下部是可滚动的比较结果和候选卡。3D 桌面不占满页面。

右侧约 26%：我的 Idea 书架，明确可投放的空槽与命中高亮，下方列出已保存条目，支持“待探索 / 优先研究 / 已归档”。空间书架和可读列表同步选择。

顶栏：Lydia 品牌、项目库 / Idea 实验台 / 研究入口。图中英文文案为概念预览；正式页面沿用项目中文语言。

## Lydia 如何比较

对每个项目提取：服务对象、具体问题、使用场景、核心机制、技术栈、数据依赖、交付方式、Demo 与代码状态、资料缺口。区分项目自述与实际可验证内容；仓库链接存在不代表实现完成。

比较输出包括：共同问题或机制、各自不同之处、可组合的互补部分、不能兼容的依赖，以及尚缺的用户或市场证据。共同点旁保留参与项目与来源摘录；区分全部项目共有与部分项目相似，不把一个项目的特点写成全部共有。

候选 idea 的适合性应说明它如何符合用户的比赛约束、技能和时间。未填写约束时给出有条件的建议，不给虚构成功率。根据机制重组方向，说明相对输入案例的变化，避免仅改名或简单拼接标题。没有搜索其他来源时，不能宣称全球首创或没有竞品。

## 每张候选卡包含什么

- 名称与一句话说明。
- 目标用户、场景与待解决的问题。
- 借鉴了哪些项目、哪些机制、各自来源。
- 共同点如何转成新方向，与原案例的差异。
- 适合当前团队或比赛条件的理由及前提。
- 最小可演示范围、关键依赖与难点。
- 尚未证实的假设，以及第一个验证动作。
- “收藏”与“查看依据”操作。

默认仅展开名称、说明、来源和首个验证动作，其余放进详情，避免挤满主面板。候选标为“待验证 idea”，不自动变成已确认的市场机会。

## 收藏到底保存什么

收藏是独立持久记录，不移动原 Hackathon 项目。保存候选正文、生成时的项目 ID 与版本、来源映射、比较结果、用户约束、生成时间和用户备注。默认保存快照；原项目更新时显示可重新分析，不静默改写已收藏内容。

同一候选在同一书架重复投放只定位已有条目。用户编辑自己的 idea 产生版本，保留最初依据。输入项目后来被移除或不可用时，仍保留已有快照及来源失效提示。

拖到书架只收藏，不自动选择研究 Gap、不自动运行商业模式任务，也不改写现有 Lydia 的显式选择规则。“交给 Lydia 研究”才把它作为项目背景，并保留候选与原案例关系。

## 状态、失败与替代操作

空实验台显示拖入引导；仅一个项目可做拆解，但共同点比较提示需至少两个项目。建议首版上限 6 个，超出时明确提示。

生成中显示可取消任务及真实阶段；失败保留选择与已生成的可用结果。改变输入后将旧结果标为“基于上一组项目”，不能混为新分析。

新增设计的拖拽使用鼠标和键盘均可触达的“加入实验台 / 收藏”按钮替代。手机用三个页签“选项目 / 分析 / 我的书架”，不要求跨屏拖拽。低性能或减少动态效果模式保留完整列表与操作。

## 与当前代码的关系

现有基础：比赛项目和来源版本、采集与导出、PROJECT 导入、专家方法、RAG、CLI 队列、任务恢复与引用检查。

需要新增：比较会话、源项目选择、专用比较与 idea 输出契约、生成任务、Idea 收藏与版本、拖拽交互、实验台及书架空间视图。当前 research.ts 的任务路由不等于已支持这个流程，不能直接把比赛项目当 MARKET 需求证据。

落地建议数据对象：idea_sessions（选择与约束）、idea_analysis_runs（输入版本与比较）、idea_candidates（候选与来源）、idea_saves（书架和备注）。这些是拟议对象，未建表或迁移。
